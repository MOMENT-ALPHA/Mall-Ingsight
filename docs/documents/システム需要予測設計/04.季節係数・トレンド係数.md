# 季節係数・トレンド係数

- 文書状態：初版案

- 作成日：2026年8月28日
- 更新日：2026年8月28日
- 対象システム：ECモール統合分析システム「Mall Insight」
- 参照資料：[[要件定義書#FR-012 季節性・販売トレンドの反映|要件定義書.FR-012]]、[[要件定義書#FR-015 複数年実績による季節係数の自動算出|要件定義書.FR-015]]

本書は、月ごとの売れ方の偏りを表す季節係数と、伸び・落ちを表すトレンド係数の算出を定める。全体の位置づけは [[01.システム需要予測設計#2. 予測の全体像|システム需要予測設計.第2章]] の工程02である。

## 1. この工程で決めること

平均日販だけでは「12月はよく売れる」「2月は落ちる」といった毎年の偏りを予測に反映できない。ここでは次の2つの倍率を求める。

| 係数     | 表すもの               | 例                 |
| ------ | ------------------ | ----------------- |
| 季節係数   | その月が普段の月と比べて何倍売れるか | 12月 1.35＝普段の1.35倍 |
| トレンド係数 | 商品全体が伸びているか落ちているか  | 1.10＝1割の伸びが続くと見る  |

いずれも1.0が「普段通り」である。

## 2. 季節係数の考え方

月ごとの販売数量をそのまま比べると、日数の違い（2月は28日、3月は31日）と欠品の有無が混ざる。
これを避けるため、月別の「平均日販」を比べる。

```text
月別平均日販     = その月の補正済み販売数量 ÷ その月の販売可能日数
多年度月別季節係数 = 対象月の加重平均日販 ÷ 全12か月の加重平均日販の平均
```

分母を全月の平均とするため、12か月の係数の平均は1になる。

### 2.1 算出例

3か月分だけを抜き出した例である（実際は12か月で算出する）。

| 月 | 加重平均日販 | 全月平均 | 季節係数 |
| --- | --- | --- | --- |
| 11月 | 2.0 | 2.0 | 1.00 |
| 12月 | 2.7 | 2.0 | 1.35 |
| 1月 | 1.4 | 2.0 | 0.70 |

12月は平年の1.35倍、1月は0.70倍の需要と見る。

## 3. 算出単位と必要な実績

| 項目           | 内容                                                     |
| ------------ | ------------------------------------------------------ |
| 既定の算出単位      | 対象品番。品番に属する全SKUの実績を合算して算出し、その品番の全SKUへ同じ係数を適用する         |
| SKU単位を採用する条件 | そのSKU単体で必要年数を満たし、かつ対象期間の月平均販売数量が最低販売数量（初期値20個）以上であること  |
| 必要年数         | 同一月の有効実績が2年分以上あること（最低有効年数、設定値）                         |
| 品番でも不足する場合   | カテゴリー単位へ上げる（[[07.実績不足時の補完と例外商品#3. 補完階層と算出単位\|07.第3章]]） |
| 12か月の扱い      | 12か月をひとまとまりとして扱う。1か月でも算出できない月がある場合、その単位の係数を採用せず上位階層へ移す |

品番を既定の単位とするのは、1SKUの販売数量が月1〜2個の水準であり、月別平均日販の比較が偶然に支配されるためである（[[06.バックテストとモデル選択#3.2 SKU単位で選ばない理由|06.第3.2節]]）。ある月が0個、別の月が2個という実績は、係数0.0と2.0という極端な差として表れるが、季節性を表していない。予測方式の選択単位（品番）とも揃う。

カテゴリー単位へ補完する場合、係数の集計元には、商品マスタに登録済みで品番との対応およびカテゴリーを判定できるSKUの実績だけを使用する。対象品番以外のSKUもこの条件を満たせば集計元に含めるが、商品マスタ未登録、品番未設定またはカテゴリー未設定のSKUは含めない。カテゴリー係数を適用して需要予測を出力するのは、選定された対象SKUだけとする。

月ごとに算出可否が異なる状態で、算出できた月だけ下位階層、できない月だけ上位階層とすると、係数の水準がそろわず正規化が成立しない。このため月単位の混在を認めない。

## 4. 複数年の重み付け

古い年と新しい年を単純平均しない。新しい年を重く評価する。

季節係数の年度は、4月1日から翌年3月31日までの会計年度で区切る。年度名は開始年を使用し、例えば2026年度は2026年4月1日から2027年3月31日までとする。係数算出日が属する会計年度を直近会計年度とし、そこから過去へさかのぼって年度別重みを割り当てる。

```text
加重平均日販 = Σ(会計年度ごとの月別平均日販 × 年度別重み) ÷ Σ(使用した会計年度の年度別重み)
```

| 項目          | 初期値                    | 根拠                                                                                             |
| ----------- | ----------------------- | ---------------------------------------------------------------------------------------------- |
| 予測に利用する実績年数 | 直近3会計年度以内                  | 初回取込の対象が2023年7月11日以降であり、利用可能な実績が約3年分であることによる（[[要件定義書#FR-015 複数年実績による季節係数の自動算出\|要件定義書.FR-015]]） |
| 年度別重み       | 直近会計年度 0.5／1年度前 0.3／2年度前 0.2 | 直近の売れ方を重く見る                                                                                    |

- 月ごとに、実績が存在する会計年度の重みだけを使用する。直近会計年度の未到来月や、初回取込開始前の月は実績なしとして扱い、存在する会計年度の重みだけで割り戻す（重みの再正規化）。
- 再正規化後も、同一月について2会計年度分以上の有効実績が必要である。
- 利用年数の設定を変更した場合は、季節係数と需要予測を再算出し、利用年数を係数バージョンとして保持する。
- 実績が蓄積した後は、設定変更で直近5会計年度以内まで拡大できる。

## 5. 正規化

季節係数は、12か月の平均がちょうど1になるよう最後に割り戻す。

```text
正規化済み季節係数 = 季節係数 × 12 ÷ Σ(12か月の季節係数)
```

補完や年度重みの再正規化を経ると、12か月の合計が12からわずかにずれる。これを放置すると、月別予測の合計が年間予測と一致しない。

季節係数は次の2つの表し方があり、意味は同じである。画面では取り違えを避けるため倍率表現に統一する。

| 表し方 | 12月の例 | 12か月の合計 |
| --- | --- | --- |
| 倍率表現（本設計で使用） | 1.35 | 12.00 |
| 構成比表現 | 11.25% | 100% |

```text
構成比表現 = 倍率表現 ÷ 12
```

[[要件定義書#13. 計算・データ品質ルール|要件定義書.第13章]] の「季節係数の年間合計が100%でない場合」は、構成比表現での合計を指す。倍率表現では合計が12であることを検証し、ずれる場合は警告のうえ正規化する（[[09.予測エラー・警告|09]]）。

## 6. 期間に対応する季節係数

30日・60日・90日の期間は月の境目をまたぐ。期間に対応する季節係数が必要な場合は、期間に含まれる日数で加重平均する。

```text
期間の季節係数 = Σ(各月の正規化済み季節係数 × その月に含まれる日数) ÷ 期間の日数
```

## 7. トレンド係数

### 7.1 考え方

直近の平均日販と、より長い期間の平均日販を比べれば、伸びているか落ちているかが分かる。ただし単純に比べると季節の影響が混ざるため、両方から季節の影響を取り除いてから比べる。

```text
季節調整済み平均日販 = 期間の平均日販 ÷ 期間の季節係数
トレンド係数         = 季節調整済み30日平均日販 ÷ 季節調整済み90日平均日販
```

### 7.2 適用の規則

- トレンド係数は上下限で丸める。初期値は0.80〜1.25とする。短期の変動が12か月先まで拡大することを避けるためである。
- 予測期間の全月に同じトレンド係数を適用する。月が進むごとに掛け合わせて累乗しない。12か月後に1.1の12乗（約3.1倍）となるような外挿を行わない。
- 90日平均日販が0または算出不能の場合、トレンド係数を算出せず「トレンド不能」とする。1.0で代替しない。
- トレンド係数は季節係数と同じ単位（既定は品番）で算出する。季節係数が得られない場合は季節調整ができないため、トレンド係数も算出しない。この場合、季節補正モデルおよび季節・トレンド補正モデルを候補から除外する（[[06.バックテストとモデル選択#7. モデル選択の規則|06.第7章]]）。
- 季節性・トレンドの使用可否は設定で切り替えられる（[[要件定義書#FR-012 季節性・販売トレンドの反映|要件定義書.FR-012]]）。
